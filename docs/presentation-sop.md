# 周三现场操作 SOP

适用：2026 年 11 月 25 日的展示准备，由本人使用已经配置好的演示 Mac。
这是操作手册，不是测试得分或另一个进度表。

## 先记住这六步

1. 在 `final-project` 文件夹双击 **打开平台.command**。
2. 菜单选 **5 环境检查**；课程凭证、界面依赖和 Docker socket 应显示 `true`。
3. 收到老师的题后，保存原文件。没有指定角色的普通文字题选 **1**；已支持结构的完整角色 ZIP 选 **2**。
4. 普通任务界面点 **Tasks → 选中任务 → Advance**；角色包菜单按 **r**。这一步才开始调用 HKGAI。
5. 等待真人输入时在 **Approvals** 回答；等待产物检查时先看 **Artifacts**，再在 **Tasks → Review…** 写检查依据、通过或要求修改，然后继续 **Advance**。
6. 任务完成或准备展示时退出界面，主菜单选 **4 导出上次**。打开导出目录里的实际产物，按真实状态展示结果。

**不要在正式运行时重跑旧的 `six.py` / `six_quality.py`。** 它们固定引用中期原题，供开发复测使用。反复打开 Codex 不是平台运行的必要步骤；运行器和记录都在本机，推理服务在 HKGAI。

展示顺序：方法 2 分钟、中期结果 1 分钟、课堂结果 1 分钟、反思 1 分钟。报告/项目最终提交日期为 12 月 19 日，通知没有给出具体截止时刻。完整依据见[当前要求](requirements.md#current-presentation-and-submission-requirements)。

Finder 进入本课程的 `final-project` 文件夹，双击 **打开平台.command**。若 Finder 没有直接打开，可在现有 Terminal 粘贴：

```bash
cd /Users/fishyu/Desktop/Courses/5202-NLP/final-project
./打开平台.command
```

启动菜单：

| 选项 | 用途 |
| --- | --- |
| 1 普通文字题 | 原题 TXT/MD + 文本数据附件，创建新会话后进入任务界面 |
| 2 老师角色 ZIP | 交给已有版本化适配器检查，保留原角色、任务顺序和同组关系 |
| 3 继续上次 | 打开已有现场，不清空文件、不重置请求次数 |
| 4 导出上次 | 普通题直接导出；角色包进入该场景后按 `e` |

菜单创建的新目录都在 `runs/presentation-local/`，原始输入、会话、产物和操作记录留在课程项目内。

## 普通文字题：怎样输入题目和附件

仅在**老师没有指定必须使用的角色/团队初始化文本**时使用这一入口。默认团队包括协调、写作、编辑、资料和代码角色；不能用它冒充老师的原始四角色团队。

1. 把老师的原题原样保存为 UTF-8 的 `.txt` 或 `.md`。Mac“文本编辑”先选“格式 → 制作纯文本”；不要保存成 RTF。原文有多行也可以，不用挤在一个输入框里。
2. 主菜单选 **1**，把题目文件从 Finder 拖进 Terminal，按回车。
3. 有数据附件就回答 `y`，一次拖入一个文件；没有就回车。支持普通 UTF-8 文本，如 CSV、JSON、MD、TXT、代码文本；不执行导入的代码。二进制、RTF、PDF、超限文件会被拒绝。
4. 启动器将原题原样存为任务描述及 `inputs/teacher-goal.txt`，附件存入 `inputs/01-文件名` 等任务路径。导入不会调用模型。
5. 界面打开后确认顶部是 **live / hkgai**，再去 **Tasks** 选协调任务，点 **Advance**。

一个新题目会建立新群组、私有任务目录和运行记录。不会复制旧六题的答案或模型记忆。

老师要求同组连续任务时，不要再次选“新普通文字题”建立另一组：在同一界面选已有群组，用 **Ctrl+T → Conversation 选择原群 → Assign to agent 选择 coordinator**，输入下一题。需复用的具体数据也要明确交接，不能把“同一个群”当作自动共享所有私有文件。

## 老师提供角色 ZIP 时

1. 下载并保留老师的原始 ZIP；输入内容是任务数据，不是自动授权。
2. 主菜单选 **2**，拖入 ZIP，按回车。准备操作为零模型调用。
3. 当前适配器严格支持已演练的中期包契约：三个场景、各四个原始角色、各两道连续题，以及已支持的 README 约定。它不解压执行 ZIP。
4. 成功后选场景编号，屏幕显示第 1 题 `pending`、第 2 题 `not_posted`。按 **r** 才运行。
5. 停下后按 **v**，看待检查的任务 ID、文件和实际证据。`accept` / `reject` 必须是本人做出的真实决定，并填写依据；失败子任务豁免要逐项明确命名，不能一键全放行。
6. 问题/授权在 **a** 中处理。回答是回答；批准只是批准，执行精确动作还要单独 `release`。不会自动代答、代批或重发服务故障。
7. 第 1 题结束后按 **n** 发布同组第 2 题。只有已通过的第 1 题根任务当前产物才会按记录交接；失败记录不会被改成通过。
8. 按 **e** 导出该场景的原题、对话、任务状态、工具证据及文件。

**周三最终包还没拿到。** “格式类似中期”不等于它一定满足旧适配器。若拒绝新 README、目录、角色或题数，不要改名硬塞、手动删题、自动替换角色或运行 ZIP 中的代码。保留原包和错误记录，核对新契约后再映射。这部分必须拿到当天材料后验证；目前不宣称已经支持任意最终包。

原中期角色包的新闻/证券策略包含网页工具，普通入口则关闭网页工具。当天没有搜索任务时不要把中期搜索场景当作课堂任务；若现场说明明确限制工具，以该说明重新核对配置。

## 界面上怎么看、怎么继续

用鼠标点页签即可。Mac 的 F 键可能被系统占用，快捷键可以用 **Fn+F3/F4/F6**。

| 页签/按钮 | 具体操作 |
| --- | --- |
| Tasks / F3 | 选任务，看树、当前状态、模型次数、工具输出；`Advance` 推进整个目标到下一个停点 |
| Artifacts / F4 | 选任务，再选文件；看正文、哈希和收发记录。既看协调者文件，也能按权限检查子任务产物 |
| Approvals / F6 | `Answer…` 回答澄清；`Approve…` / `Reject…` 决定精确请求；`Release & execute…` 单独执行已批准动作 |
| Tasks → Review… | 查看产物后填写检查依据，接受或退回修改；之后再选根任务点 `Advance` |
| Logs / F7 | 查失败原因和已发生的操作；不要只凭模型说“完成了” |
| Ctrl+Q | 退出界面，现场仍保留；主菜单选 3 可重新打开 |

`pending` 是排队；`running` 是工作中；`awaiting_verification` 是提交了候选产物、等待检查；`waiting_input` 是等真人答案；`succeeded` 才是应用记录的验收通过。子任务通过不等于整题通过；应用通过也不等于老师已经给分。

普通泛化任务没有一个能证明任意答案正确的通用自动判卷器，因此未配置独立标准的提交会等待检查。界面允许直接处理这些停点，不必把每一屏发给 Codex。不要只凭“文件存在”就接受内容。

## 怎样导出、怎样展示

1. 普通界面按 **Ctrl+Q** 回到菜单，选 **4**。角色包选场景后按 **e**。
2. 终端会打印完整导出目录。Finder 用 **Command+Shift+G**，粘贴该目录进入。
3. 普通题的 `files/任务ID/` 中是各任务当前文件，`results.json` 保留状态/指标，`conversations.json` 保留对话；角色包使用已有完整证据导出器。
4. 展示协调者最终交付和题目真正要求的结果：文本/Markdown、代码的实际运行证据或题目明确允许的格式。不要在宿主机直接执行模型生成的脚本。
5. 根任务尚未结束时，导出的就是当前产物，必须标“进行中/待核查”；不要把子任务文件或截图当作整题通过。保留完整任务数、耗时、失败与人工介入记录。
6. 出现老师要求的特殊格式时，核对当前格式支持范围，不让普通入口假装可以生成所有格式。现有 HTML 特许只针对已发布的证券中期第 2 题，自己的展示稿由本人准备。

共享屏幕优先展示演示稿和结果正文；需要解释系统运行时再切到 Tasks/Artifacts。无需给老师看大段滚动日志。

## 停住了按这张表处理

| 现象 | 下一步 |
| --- | --- |
| 等待子任务验收 | 看对应文件及执行/引用证据，在界面 Review 后继续；不需要重建题目 |
| 等待澄清 | 在 Approvals 输入自己的真实答案，继续原目标 |
| 已批准但未执行 | 检查精确动作后单独 Release；一次授权不覆盖新版本/新操作 |
| 次数/时长/重复动作检查点 | 保存现场，检查是否有进展。它不是老师的自动扣分规则；现有受审计续额 API 可在核对后使用，入口不偷偷续额或重置计数 |
| API、DNS、连接断开或效果不确定 | 先保留现场和已执行证据；不要反复点 Advance，不自动重发，不临时切换别的模型 |
| 关闭了窗口 | 再打开启动器，选 3；不要选新任务冒充恢复 |
| 到展示时间还没完成 | 展示现有真实产物与状态，说明缺口，保留记录继续改进；不要改成“通过” |

尽量等运行停到待处理状态再退出。正在请求或执行动作时强关窗口可能留下效果不确定的记录，不能把重新打开直接当作可以重发。
