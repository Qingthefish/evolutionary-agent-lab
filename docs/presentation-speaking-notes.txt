一 时间怎样留

当前五段英文按空白分词为 104 / 99 / 98 / 71 / 67，共 439 词。
第四段占位字段各计一个词，填完后重新计数、重新计时。
以 110 词/分钟估算，纯正文约 3 分 59 秒；加指图、演示与窗口切换，
整套展示目标 4:20–4:30，留约 30 秒余量。这个目标包含课堂结果和结尾。
不能把静态内容先讲 4 分半，再额外添加一分钟现场结果。
老师要求方法 2 分钟、中期 1 分钟、课堂 1 分钟、反思 1 分钟，按这个顺序展开。
上面的时段标题是各段的预算，不是要求每段精确念满。实际人声计时尚待本人完成。

Slide 1：Task coordination and file handoff
讲持久化任务树、负责人委派、调度 eligible tasks、SQLite 状态和对话。
重点不是“好几个模型一起聊”，而是每个任务有受控文件，交接精确版本。
把开发任务、SHA-256 快照、QA 接收依次强调。接着用预订系统延伸仪表盘说明同组续题。
代码依据：agent_lab/core.py、scheduler.py、files.py、evaluation/official_session.py。
讲的是目前实现的机制；不说已经证明任何长任务都能自主规划。

Slide 2：Controlled execution and recovery
讲 Tool Gateway 绑定任务身份，执行前检查权限；Python 进入独立新容器，
无网络、无宿主目录挂载，记录输入哈希、退出状态和导出文件。
关键操作的批准绑定具体动作/参数。SQLite 保留运行状态，便于检查后续做。
选两个实际修复讲：截断回复改为小段/局部文件编辑；中断运行保留检查点、明确恢复。
结尾用一句 Git 工作阶段和 953 项工程检查交代工程投入，不逐条念提交历史。

Slide 3：Mid-test results
屏幕直接放两行有条件的结果，不反复口播统计免责声明：
  Review and repair assistance       6/6 accepted       633 HKGAI calls
  Fresh first-proposal check        4/6 accepted       600 HKGAI calls
先讲辅助修复后六题全部技术验收，再讲新建组的严格复测四题通过。
最新复测在首次提交的子任务出现实质错误时停止整题；这是一项本地开发检查规则。
普通偏好仍由被授权的操作员选择，并有独立技术检查，不是完全无人介入。
软件 2/2、新闻 2/2、投资 0/2。两项投资风险子稿分别有汇率转换及估值/政策解释问题，
都没撞限额，也未进入最终配置/HTML 交付。原样保留失败记录，不把两轮混成一轮。
原始 375 次四项协助验收/两失败轮次留报告备用，主讲一分钟不再堆第三套数字。

Slide 4：Classroom result
老师发题后，在原会话核对真实格式、原题、附件、角色和任务顺序，再运行。
这一页显示：题目一句话、实际产物、关键检查、完整耗时和真实状态。
完成且验收后才用正文的完成版本。没完成或服务中断，用下方替换版本。
结果图可放在 PPT 倒数第二页，随后用最后一页/几句反思收尾。
也可在这一分钟直接共享已经打开的产物窗口，不必等新图做好才展示。

Slide 5：Reflection
结尾讲实际难点：可靠交接、怎样确认工作已做好。再讲一个发现：
计算程序运行成功仍可能解释错，后续要把数字/单位/结论复核放进团队内部，
并在新任务中继续验证经验复用。不开泛泛的免责声明，也不虚构学习收益。

三 第四页的现场替换正文

A 已完成并验收
使用英文主稿第四段，填写四项：
[TASK] 原题的简短描述；[OUTPUT] 实际交付文件或功能；
[CHECK] 实际做过的关键检查及结果；[TIME] 从发任务到交付的完整耗时，包含等待和检查。
填好后调整语法。尚未验收，不能念 reached acceptance。

B 已有产物，任务还在继续

Here is the task we received tonight: [TASK].

The team has produced [OUTPUT]. We checked [CHECK]. The task is currently [STATE], with [NEXT STEP] still pending.

The screen shows the current artifact and its execution record. We exported this version and kept the task history, so we can resume from the same point after the presentation.

The elapsed time so far is [TIME], including waiting and review.

C 服务或运行中断

Here is the task we received tonight: [TASK].

The request stopped with [OBSERVED ERROR], and the task is [ACTUAL STATE]. We saved the files, task state and request history. [ACTUAL RECOVERY ACTION].

On screen, I can show [AVAILABLE EVIDENCE]. The elapsed time is [TIME], including waiting and inspection. We will use the retained record to decide how to continue from this point.

[ACTUAL RECOVERY ACTION] 只填实际做过的事，未重发就不说已重发。
三种版本只选一种。填写后重新计时，保留真实状态。

五 今晚的现场图和结尾怎样衔接

七点多继续在当前 Codex 对话里即可。保持相同工程目录，先发老师实际题包/本地路径，
并说明运行状态。原始运行和导出记录也保存在工程内，不只依赖聊天记忆。
先按 SOP 运行实际题，再核对已产生的文件和关键检查。

如果结果及时出来，我可以沿用现成风格，把真实产物截图、任务状态、检查结果和耗时
整理成一张可插入 PPT 的成果页，并将主稿第四段改为对应的短结尾。
这依赖当时服务、文件和证据可用，不能提前承诺具体秒数。
时间紧就先共享真实产物或导出文件，现成图页不是开始展示的前提。
不要预先填写通过状态、时间或成果图，不用重跑原六题来充当课堂结果。

完成时可用的短收尾（拿到结果后填写）：
The team delivered [OUTPUT] for [TASK]. [CHECK RESULT] confirms [VERIFIED POINT].
This is the version exported from tonight's run. Our next step is [NEXT STEP].

未完成时可用的短收尾：
The team has produced [OUTPUT]. [REMAINING STEP] is still in progress.
We have saved the current version and can continue from the same state.
