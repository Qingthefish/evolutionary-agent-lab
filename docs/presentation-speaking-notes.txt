五分钟展示讲稿使用说明
更新日期：2026 年 11 月 25 日；用于当天晚上的五分钟展示。
英文正文在 docs/presentation-script.txt。本文是中文提示、PPT 对应内容与替换段，
不作为逐字朗读正文。讲稿不是产品新增功能，也不是最终报告或进度表。

一 先校正项目和展示的定位

项目是通用多 Agent 协作平台。ZIP 是老师分发角色、任务和附件的测试入口，
不是产品只为 ZIP 或原六题设计的定义。平台程序和文件在本机，模型推理通过
HKGAI API 进行；正式运行仍需要网络。现场使用已测试版本，保留原题和角色。
最终课程交付还包括 GitHub 源码与真实贡献记录、架构说明、性能和失败分析报告。
个人 PPT 由本人手工制作；这次不改 PPT 文件、不改平台代码、不调用模型。

五分钟不是按开发日期讲流水账。老师指定的顺序是：
方法 2 分钟，中期结果 1 分钟，课堂结果 1 分钟，反思 1 分钟。
迭代故事放在方法和反思里，围绕“实际失败—机制修改—如何检查”讲。
不是每一轮都单调提升；不同题目、协助和停止规则需要单独报告。
可选两个例子：长回复截断后分段/局部编辑；计算错误经独立检查反馈后修复。

二 字数和节奏

英文正文按空白分词统计（只计五页段落，不计标题和开头说明）：
第 1 页 101 词；第 2 页 95 词；第 3 页 104 词；
第 4 页 89 词；第 5 页 97 词。合计 486 词。
第 4 页四个占位字段各算一个词；填好后总词数会变化，字段总量尽量不超过 20 词。

这不是已经测得的五分钟。486 词按 110–115 词/分钟估算，正文约 4 分 14 秒到
4 分 25 秒；再留 15–20 秒指图、翻页和切结果。填好现场字段后重新计时。
你可以用自己的自然语气讲，不必照着 PPT 念完整句。老师规定五分钟，
所以至少完整计时读两遍，再练一次从 PPT 切到已打开的结果窗口。

如果试读偏慢，先删下面四句，共 39 词；正文变为约 447 词（现场字段另算）：
1. The team can extend its work while preserving where each file came from.
2. Service interruptions remain recorded and require an explicit recovery decision.
3. The file on screen matches the version we reviewed.
4. Today's classroom result will add another observation.
保留两轮六题的协助/判定口径、未知题区分、真实耗时及记忆收益的限制。

三 五页 PPT 与口头过渡

Slide 1  How the team works  0:00–1:00
屏幕关键词（最多三个）：
  Goal → lead → delegated work
  Private workspaces and explicit file handoff
  Same group for the follow-up task
配图：一个简单的角色协作流程；用会议室第一题到仪表盘第二题说明。
讲法：直接从“我们做了什么、它怎样接任务”开头，不做领域背景介绍。
强调角色可以委派，不说每次运行一定使用所有成员。
结尾自然转到：任务会协作之后，怎样约束执行并恢复失败？

Slide 2  Execution and recovery  1:00–2:00
屏幕关键词：
  Checked tool actions and isolated execution
  Human questions and critical decisions
  Inspect → repair → resume
配图：工具动作、检查、隔离执行、验收四步；旁边放一个截断/恢复例子即可。
讲法：选两项改进讲清原因，不逐项念 Git 历史、不罗列所有调试次数。
“保存检查点、检查后继续”不等于取消所有运行控制，也不等于无限自动重试。

Slide 3  Mid-test results  2:00–3:00
屏幕用一张两行简表，把条件与成绩放在同一行：
  Assisted known-task development | 6/6 accepted | 633 HKGAI requests
  Fresh first-proposal diagnostic | 4/6 accepted | 600 HKGAI requests
表下写一句：Different review conditions; not an unseen-task success rate.
旁边小字标出：No external technical repair; material child error stops root.
953 项工程检查放到第二页角落，口头一句带过，不把它画成任务准确率。
六题按 software / newsroom / securities 三组排列，每组两题。
两轮均是已知中期题开发记录。6/6 有修复反馈；4/6 没有外部技术修正，
但有两次按授权作出的偏好选择和独立技术检查，不是无人介入。
最新规则在风险子稿首次出现实质错误时就停止整题；它比只检查最终交付更严格，
并非老师判分标准或产品正常运行时必须采用的停止规则。
软件/新闻四题通过；证券两题暴露汇率和估值/政策解释问题，未到最终配置/HTML交付。
两题都没撞限额。不要说“只要再多给几次就肯定全对”。
原始 375 次、四项协助验收/两失败那轮留在备查材料，不在一分钟里再堆一行。
不把三轮拼成一次最佳成绩，不承诺整个浏览器交互都已验证。

Slide 4  In-class results  3:00–4:00
屏幕只放：实际题目一句话 + 一个清晰的实际产物 + 状态/完整耗时/介入说明。
老师要求看到结果，没有要求整段任务在上台后才启动，也没有要求结果全嵌进 PPT。
提前留好这一页；拿到真实材料后填四个短字段，或按下述情形换整段。
想直接切到产物，也先打开对应文件；别临时滚动整屏 Terminal 找结果。

Slide 5  What we learned  4:00–5:00
屏幕关键词：
  Traceable versions and execution evidence
  Correct execution still needs correct interpretation
  Unseen evaluation and learning evidence remain open
讲法：先说什么确实有效，再说什么没有证据；最后给出 12 月 19 日前的具体改进方向。
私人经验记录已有机制，不能因此说系统已证明“越跑越聪明”。
我们没有做出一般性的记忆学习提升结论，保留这句话是对课程“evolution”要求的真实交代。

四 第四页现场替换

A 已完成且验收通过
使用 presentation-script.txt 中的第 4 页，填：
  [TASK]：老师真实任务的短描述。
  [OUTPUT]：真实交付的文件或功能。
  [CHECK]：实际执行过的一个核心检查及结果。
  [TIME]：从任务发布到当前交付的完整耗时，计入等待和检查。
先核对根任务状态和最终文件。接受的是应用技术验收，不是老师已经给分。
别填旧六题成绩、今天练习结果或纯模型耗时。

B 有产物但仍未完成
整段替换为以下英文，不与 A 同时朗读：

Now I'll show the task we received in class: [TASK].

The team has produced [OUTPUT], which you can see here. We have checked [CHECK].

The overall task is still [STATE]. The remaining step is [NEXT STEP], so I am showing this as a partial result.

We exported the current files and kept the conversation and execution records. The elapsed time so far is [TIME], including operator waiting and review. Human decisions and any technical assistance are recorded.

This shows what the system has delivered so far and what still needs work. The earlier mid-test results are reported separately.

C 服务中断或运行故障
整段替换为以下英文，不与 A/B 同时朗读：

Now I'll show the task we received in class: [TASK].

The run stopped with [OBSERVED ERROR] while requesting a model response. The record shows [ACTUAL STATE].

We kept the task state, files, and request history. [ACTUAL RECOVERY ACTION]. Any repeated request is counted separately.

On screen, I can show [AVAILABLE EVIDENCE]. The elapsed time is [TIME], including operator waiting and inspection.

We have not verified a complete answer to this task. The earlier development results remain separate. Our next step is to inspect the interruption, then continue from the preserved state when it is appropriate to do so.

[ACTUAL RECOVERY ACTION] 填实际做过的动作；未重发就不能说已重发。
若没有最终文件，[AVAILABLE EVIDENCE] 可以是任务树、实际错误及保留的状态。
不把尚未确认的原因归咎于 HKGAI，不把未验收结果写成通过。
三个版本的长度接近，但填入真实情况后仍须重新计时。

五 当天的时间和操作

所有同学到教室，使用自己的电脑，并按通知加入同一个 Zoom 共享屏幕。

不是另写的“16.5 分钟内跑完否则判失败”规则。明确的发言时限是五分钟。
通知通常没有问答；先按五分钟准备。最终提交为 12 月 19 日，截止具体时刻尚未核实。
当前通知没有要求当场另发邮件或上传 ZIP；当天若另附提交方式，以真实要求为准。

七 手工 PPT 的画面和现场剩余事项

你已经熟悉的“同图逐页加框、分步强调”方式可以保留。五分钟按五个逻辑页面，
建议五到七张实际幻灯片；若同一页复制两次用于高亮，它们共用这一分钟，
不是每翻一页重新分配一分钟。不要为每条数据复制一页。

第 1 页：平台名称与小组信息放在角落，直接画 goal → lead → delegated work，
再用文件交接和同组后续任务说明，省去独立的背景开场页。
第 2 页：一张执行/检查流程，最多两次高亮；旁边一个小的截断恢复例子和 953 工程检查。
第 3 页：6/6 assisted 与 4/6 first-proposal 的两行结果表，条件直接可见。
不同口径不能画成“4→6→4”的改进折线，也不能把 953 与六题画在同一准确率轴上。
第 4 页：一张真实课堂产物截图或切到已打开的产物，附真实状态和完整耗时；
没有结果时用上面的未完成/中断版本，不把练习产物当成现场产物。
第 5 页：可追溯文件和执行证据确实有用；金融解释仍会错；记忆收益未证明，
下一步增强内部数字/单位/结论复核，12 月 19 日前继续未知题测试。

不需要重新生成复杂插画。你手工用箭头、角色名、两行表格、一个结果截图就能讲清。
参考稿的图框节奏可以借鉴；该论文的模型、实验分数、学习提升不是本平台证据。
不用给每个阶段做一张数据图，也不要在五分钟讲 Git 提交流水账。
四人的姓名/小组信息可在第一页角落列出，真实贡献历史截图放备用页，
不把团队实现和助手参与写成主讲者一人的独立工作。

一个人主讲符合老师要求；所有组员仍需按通知到教室现场，并按安排使用同一 Zoom。
组员不必各讲一段，也不用临时各自补一套 PPT。你负责电脑、主讲和操作；
PPT 按自己的节奏制作，完成后两次计时，检查投屏切换及大字是否可读。

Git 快照（2026-11-25 本次检查时）：main 已与远端同步，工作区干净，
四个组员对应账户均有实际合入的提交，已有四份真实历史截图。

也不能说仓库完全没有待办。今晚使用已测试版本，不临时混入未审新代码。
